# 24 · 综合交付：短链接服务——把 23 个实验装进一个应用

> 学过的零件只有装成整机才算学会。本实验交付一个完整短链接服务：参数校验、
> 统一错误信封、鉴权依赖、依赖工厂、request_id、配置、热点缓存各就各位。
> 它能跑、能断言、也诚实地标注了生产化缺位。

## Background

零件知识掌握后有个常见窘境：单件都会写，拼在一起就乱——校验写在路由里、
错误格式各端点不同、缓存与统计互相打架。

综合交付的价值就是把"装配顺序"练成本能：先定错误契约（信封），再定数据
与鉴权，最后叠性能件（缓存）。短链接服务足够小（一个域模型），又足够全
（读写、跳转、统计、鉴权、缓存都有）。

## What

**短链接服务**把长 URL 换成 6 位短码：`POST /links` 创建，`GET /{code}` 307
跳转，`/links/{code}/stats` 看点击，`POST /admin/reset` 用管理密钥清场。

可以把整套服务想象成**寄存处**：存包给牌（创建），凭牌取包（跳转），牌子
上的小格计次（统计）。但和寄存处不同的是，取包凭证可以无限复制——短码
不是秘密，保护的是管理端点而不是跳转本身。

| 功能 | 串联的实验件 |
|:--|:--|
| URL 校验 + 422 信封 | lab 01/02 校验、lab 04 信封 |
| 跳转 307 + request_id | lab 19 中间件贯穿 |
| 热点跳转缓存 | lab 22 TTL 缓存 |
| 管理端点鉴权 | lab 08 依赖、lab 17 密钥语义 |
| 短码长度可配 | lab 10 依赖工厂、lab 21 Settings |

一次创建与一次跳转的完整数据流：非法入参在中途汇入统一信封，热点短码由缓存接管跳转，计数始终走主表。

## When to Use

- 学完一个框架想验收时：造一个这样的"小而全"服务，比再读十个 demo 有效。
- 经典系统设计题（设计短链接）的动手版：先跑通再谈扩容。
- 何时不用：不要把它当生产代码——持久化在内存、多 worker 各一本账，
  这些缺位正是下一段的诚实预期。

## Quick Start

前置：fastapi 目录 `.venv` 已就绪，未创建则先在仓库根执行
`./scripts/load_resources.sh`。运行：

```bash
cd fastapi/24_url_shortener && ./24_url_shortener.sh all
```

真实输出（节选，`...` 处省略了中间输出；短码与 request_id 每次运行都不同）：

```text

    POST /links -> 201 {'code': '2ivqag', 'short_url': '/2ivqag', 'reused': False}
    重复创建 -> 201 reused=True code=2ivqag
    [PASS] 短码 6 位, 同 URL 复用同码

=====> [4/6] 边界现场: 422 / 404 / 403 全走统一信封
```

诚实预期：短码与 request_id 每次运行不同（随机生成）；统计数字（3 次跳转
clicks=3）恒定；热点缓存节的毫秒数随机器浮动，断言只锁"缓存后不更慢"。

## How It Works

**缓存与统计的职责分离**：第一版把"计数"写进了缓存未命中的回调里，结果
命中缓存的跳转不计数——统计悄悄少了。修法是把"解析 URL"（可缓存）与
"记录点击"（必执行）拆开：缓存只管省查表，统计无条件走主表。

**路由注册顺序**：全捕获路由 `/{code}` 会把 `/healthz` 也当成短码吃掉。
固定路径必须注册在 catch-all 之前——这是本实验实跑撞出来的第一个坑。

**查重先于发码**：同一 URL 返回同一短码，避免码空间被重复浪费；发码前
while 循环重抽处理 base62 碰撞（6 位 62⁶ 空间，概率极低但处理要存在）。

## Pitfalls & Q&A

- **缓存旁路了副作用**：把"有副作用的逻辑"（计数、扣款）塞进可缓存的
  回调里，命中即丢失。副作用必须放缓存之外。
- **catch-all 路由吞噬固定路径**：`/{code}` 注册在前，`/healthz` 永远 404。
  固定路径先注册，或给短码加正则约束。
- **管理密钥硬编码**：演示用常量，生产从环境注入（lab 21）并定期轮换。
- **内存存储的边界**：重启即丢、多 worker 各一本账——正解是数据库
  （lab 15）加集中缓存（lab 22 的 Redis 边界）。

**Q：为什么跳转用 307 而不是 301？** 301 会被浏览器永久缓存，之后改目标
地址用户再也到不了新地方；307 临时重定向每次都问服务器，短链接改址、
统计都靠这一点。

**Q：短码碰撞怎么办？** 先查重再落库、碰撞重抽（本实验的做法）；规模化后
换成"自增 ID 转 base62"，天然无碰撞且可排序。

**Q：要上多 worker 需要改哪里？** 三处：LINKS 换数据库（lab 15）、缓存换
Redis（lab 22 边界）、计数改原子自增——本实验的内存版就是为了让这些
缺位显眼。

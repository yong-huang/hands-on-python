# 10 · 异步生产者-消费者与限流：asyncio.Queue、Semaphore、背压

> 项目 4 把流水线建在线程上，这一篇搬进单线程世界：`asyncio.Queue` + `Semaphore` +
> `maxsize` 背压。实测数据先看一眼——5000 条任务 0 秒级跑完（204 万条/秒）、
> 在飞峰值被 Semaphore 钳在 10、无界队列峰值 4749 vs 有界 64。

## 1. 为什么需要它

线程版流水线（项目 4）的每一次 put/get 都有锁竞争和线程切换；asyncio 版只有一个线程，`await q.put()` 的"阻塞"只是让出控制权——同样的结构，调度成本降到函数调用级。但组织纪律一样不能少：**总量守恒**（毒丸收尾）、**并发上限**（Semaphore 许可）、**内存上限**（maxsize 背压）。三者就是后面高并发抓取器（项目 11）的全部骨架。

## 4. 核心概念

### 4.1 asyncio.Queue：给协程用的传送带

与 `queue.Queue`（线程版）API 几乎一致，但 put/get 是 **await** 的：队列满时 `await q.put()` 挂起生产者，空时 `await q.get()` 挂起消费者——等待是让出控制权，不是阻塞线程。毒丸收尾协议原样适用（None 哨兵 + task_done + join）。**关键差异：单线程内没有数据竞争**，计数 dict 不需要锁（但仍要保证单条消息只被一个消费者处理——Queue 的 get 语义天然保证）。

### 4.2 Semaphore：异步世界的并发闸门

`async with sem:` 包住"访问受限资源"的协程段，超过许可数的协程在 await 处排队。用途与线程版相同（限流爬虫、连接池），但在异步世界里它是**提高吞吐的关键工具**：单线程能挂起上万协程，没有 Semaphore 的话，一万次并发请求会同时砸向目标——限流既是自我保护也是礼貌。

### 4.3 背压：让过载反馈到源头

无界队列 + 慢消费者 = 内存里的定时炸弹（实测峰值 4749 条堆积）。`maxsize=64` 让 `await q.put()` 在队满时挂起——生产速率被自动钳制到消费速率，内存占用恒定。这就是"背压"（backpressure）：不丢弃、不报错，让压力沿流水线传回源头。

## 5. 关键代码解析

**为什么 §1 的消费者敢不用锁更新共享 dict？**

```python
results[item] = results.get(item, 0) + 1   # 多个消费者并发执行这段
```

线程版这里必须上锁（读-改-写隔调用会被切换打断）；异步版**单线程内协作式调度**——只有 await 点才会切换，而这几行之间没有 await，是原子执行的。这是 asyncio 的重要红利：**同步段天然原子**。但一旦中间插了 await，原子性即告破裂——"await 之前是安全的，之后不一定"要时刻默念。

坑清单：

- **在协程里调阻塞函数**（`time.sleep`、同步 requests）：整个事件循环停摆， Semaphore 也救不了；一律用异步库（`asyncio.sleep`、aiohttp）
- **无界队列 + 生产快于消费**：内存悄悄堆积，压测时看 QPS 不看 qsize 会漏掉——监控队列长度
- **忘了给消费者发毒丸**：`await q.get()` 永远挂起，程序退不出去（项目 4 的教训在异步世界原样成立）
- **Semaphore 包错范围**：包住整个循环体 vs 只包资源访问段，吞吐差一个数量级；锁的粒度原则同样适用于许可

## 7. 面试要点

**Q1: asyncio.Queue 和 queue.Queue 的区别？**
API 几乎一致，等待机制完全不同：前者 await 让出（单线程协作），后者阻塞线程（多线程抢占）。前者只能在事件循环内用，跨线程要用 `queue.Queue` 或 `loop.call_soon_threadsafe` 桥接。

**Q2: 异步协程里操作共享 dict 要加锁吗？**
只要读-改-写之间没有 await，就是原子的（单线程不会中途切换）。一旦中间插入 await，另一个协程可能插进来修改——要不要锁取决于**await 的位置**，这是 asyncio 特有的推理方式。

**Q3: 背压（backpressure）是什么？asyncio 里怎么实现？**
让消费端的过载沿流水线反馈到生产端：`asyncio.Queue(maxsize=n)` 队满时 put 挂起，生产速率自动对齐消费速率。对比方案是丢弃或无界堆积——前者丢数据，后者爆内存。

**Q4: Semaphore 在 asyncio 里为什么重要？**
单线程能同时挂起数万协程，无限制的并发请求会瞬间压垮目标服务（也有对自己 fd 数的限制）。Semaphore 把"同时多少个"变成一行声明，成本是一个计数器。

**Q5: 毒丸关闭在异步版有什么不同？**
协议相同（None 哨兵 + task_done + join），但发给每个消费者一枚毒丸后用 `asyncio.gather(*consumers)` 等待即可；另外 asyncio 队列的 task_done/join 语义与线程版完全一致，可以无缝迁移经验。

## 8. 总结

1. **asyncio.Queue：单线程传送带**——5000 条守恒、200 万条/秒、无锁记账
2. **同步段天然原子**：await 是唯一的切换点，"await 之前安全，之后不一定"
3. **Semaphore(10) 钳住在飞峰值**：限流是异步高并发的自我修养
4. **maxsize 背压**：无界峰值 4749 vs 有界 64，让过载反馈到源头
5. **结构与线程版同构**：毒丸、回执、守恒——换了世界，纪律不变

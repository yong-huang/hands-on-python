# 13 · 并发设计模式集：优雅关闭、令牌桶、指数退避、fan-out / fan-in

> 零散知识到工程能力的最后一公里是**模式**。这一篇把并发的常用招式提炼成四个
> 可复用模式，每个都带确定性验收：优雅关闭（kill -TERM 后 128ms 体面退场）、
> 令牌桶（100 请求恰 1.00s）、指数退避（0.77s ≈ 理论 0.75s）、fan-out / fan-in
> （3 个失败被隔离，17 个成功照常收集）。

## What

模式是带着行为契约的知识。一句话心智模型：**优雅关闭管生命周期（信号→停接活→善后→落盘），令牌桶管速率（长期平均+突发额度），指数退避管失败恢复（越挫越有耐心），fan-out / fan-in 管批量吞吐（并行扇出、失败隔离、结果归拢）**。四个模式覆盖生产并发系统的四大关切：活得好、跑得稳、摔得起、扛得住。

## Why

知道"要限流、要重试"，但写出来常常是错的：限流变成了精确等于、退避曲线随手拍、关闭逻辑靠 sleep、批处理一错全崩。模式的价值在于**每个都带明确的行为契约**——本实验的四个模式各配一条可断言的验收线，让"写对了"可以被证明。

诚实预期（本机 3 次实测）：

- **§1 落盘数 12 = 全部任务**：0.6s 内 5 个 worker 已消化完 12 个任务（每个 50ms），信号到来时"手头"只剩收尾——想看"做一半"的场景把任务 sleep 调大
- **§2 恰好 1.00s**：令牌桶的补币是精确的时间函数；±0.3s 断言带覆盖调度抖动
- **§4 的 3 个失败位置固定**（i % 7 == 3）——失败隔离的断言才能写死 17+3

### 优雅关闭：信号 → 事件 → 排水 → 落盘

`signal.signal(SIGTERM, handler)` 把信号转成 `threading.Event`，worker 循环改成"拿不到新活且关闭已触发 → 下班"。三要素：**停止接活**（不再领新任务）、**做完手头**（处理中的任务完整跑完）、**落盘**（成果持久化后退出）。对照毒丸模式（lab 04）：毒丸是"任务流内部的关闭协议"，信号处理是"进程级的关闭入口"——生产系统两者都要。

### 令牌桶：两种限流性格

令牌桶以恒定速率生成令牌，桶满允许**突发**（一次拿 50 个立刻通过）——适合"平时宽松、上限明确"的调用方限流。漏桶则强制恒定速率出口。实现核心是"按时间差补币"而不是定时器——无需后台线程，纯懒计算。

### 指数退避：对上游最有耐心

失败后等待 `base × 2^n` 再试（0.05→0.1→0.2→0.4s），给上游指数级增长的恢复时间；上限封顶 + 次数封顶 + ±jitter 防止所有客户端同步重试（重试风暴）。断言时关 jitter——**模式可以有随机性，验收必须确定**。

### fan-out / fan-in：批处理的事务边界

扇出（submit 全部）→ 并行执行 → 扇入（as_completed 归拢）。与 TaskGroup（lab 09）的本质区别：**失败隔离**——3 个失败被收集到 errors 列表，17 个成功照常交付。适合批处理（能重试的单独重试）；事务型场景（必须全成）才用 TaskGroup 的一败全停。

## Deep Dive

**为什么令牌桶用"时间差补币"而不用定时器线程？**

```python
now = time.monotonic()
self.tokens = min(self.capacity, self.tokens + (now - self.updated) * self.rate)
self.updated = now
```

每次 acquire 时按"距上次的秒数 × 速率"补币——懒计算，无需后台线程、无定时误差、多调用者天然共享。`monotonic()` 而非 `time()`：系统改时间不会让桶凭空溢出。

踩坑清单：

- **优雅关闭里等待太狠**：worker 只看 `task_q.empty()` 就退，会把已入队未领取的任务留成孤儿——"停止接活"和"排空队列"是两件事，本实现用毒丸或超时轮询保证两者兼顾
- **信号处理里做重活**：handler 只该 set 一个 Event，真正的排水逻辑在主流程里——handler 里做 IO 是死锁温床
- **退避无上限**：第 20 次重试要等 0.05×2¹⁹ = 26 小时；必须封顶次数和单次上限
- **jitter 写进断言**：模式带抖动，验收就关抖动或放大容差——别让随机性毁掉测试
- **fan-in 时不区分结果与异常**：成功和失败分池收集（本实验 errors 列表），混在一起下游无法处理

## Q&A

**Q1: 令牌桶和漏桶的区别？**
令牌桶允许突发（桶内积攒的令牌可一次性用掉），控制"平均速率 + 突发上限"；漏桶强制恒速出口。API 限流常用令牌桶（容忍 bursts），流量整形常用漏桶。
